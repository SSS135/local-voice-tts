# Shtorm Russian frontend

`backend/ShtormBpeFrontend.java` loads `vocab.json`, `token_scores.json`, and `normalizer.bin` from the separately installed model pack. The two-file constructor finds `normalizer.bin` beside the vocabulary. Construction belongs on the backend worker, after model-store integrity verification.

- `normalize(text)` returns the exact escaped SentencePiece form, including the dummy `▁` prefix.
- `encode(text)` returns actual IDs. It rejects unknown tokens, Latin text, malformed UTF-16, and overlong input before synthesis. It preserves Cyrillic case and acute stress marks. Empty or whitespace-only input yields an empty array.
- `encodeSpeakable(text)` is the synthesis path and never throws on content. It cuts malformed UTF-16 and over-long input, normalizes, drops every code point that is not a single-character vocabulary piece (Latin, digits, emoji, OOV), and then runs the same BPE. On supported text it equals `encode`.
- `encodeBridge(text)` emits bare `U+E000 + tokenId` symbols. It adds no prefix or suffix. The separately verified 8,000-entry native bridge vocabulary consumes Sherpa's own dummy prefix together with the first symbol.

`ShtormBackend` runs `RussianNormalizer` (numbers, dates, units, Latin transliteration; see `docs/RUSSIAN-NORMALIZER.md`) before chunking. The helper itself does not guess pronunciation, transliterate, or case-fold.

## Provenance

Tokenizer: genuine Shtorm model revision `33f6c328d62c4da5c1227bbe081e89b574a6183a`; `tokenizer.model` SHA-256 `95d0b8e61951408c7744e09fb5b87ff8e318612b0c8168cc593ea0a812f34f81`. It contains 4,000 BPE pieces: 3,997 normal, one unknown, and two controls, with no byte fallback, user-defined, or unused pieces.

The model's 240,007-byte `nmt_nfkc` compiled character map is used directly, avoiding host Java Unicode-version drift. `normalizer.bin` SHA-256: `5febaab28312e9dbddb42be695c9e4380367f7ebe65121cdf894fb5d59d37eed`. Its flags are dummy prefix, extra-space removal, escaped whitespace, and no whitespace suffix. The tokenizer data retains the original model license in the model pack.

Behavior follows Google SentencePiece 0.2.2, pinned at [`e0cce7d37b065b5140349dbe12c6bcf6192fdd78`](https://github.com/google/sentencepiece/tree/e0cce7d37b065b5140349dbe12c6bcf6192fdd78): [BPE rank merges](https://github.com/google/sentencepiece/blob/e0cce7d37b065b5140349dbe12c6bcf6192fdd78/src/bpe_model.cc), [normalization](https://github.com/google/sentencepiece/blob/e0cce7d37b065b5140349dbe12c6bcf6192fdd78/src/normalizer.cc), and the [compiled trie format](https://github.com/google/sentencepiece/blob/e0cce7d37b065b5140349dbe12c6bcf6192fdd78/third_party/darts_clone/darts.h). SentencePiece implementation is Apache-2.0; Darts-clone is BSD-3-Clause. The Java helper interprets the exported data and does not load the Python or C++ runtime.

## Verification

`ShtormBpeCheck` runs under `gradlew test` when the untracked `tools/models/shtorm/onnx` exists (skipped otherwise). Expected outputs were exported by genuine SentencePiece 0.2.2, not generated by the Java helper. All 160 fixtures match normalization; 146 supported cases match exact token IDs and PUA symbols, and 14 unsupported cases are rejected. The 2,401 assertions also cover case, stress, malformed Unicode, and corrupt normalization data. Evidence: `build/shtorm-bpe-checks/result.txt`.

These are host frontend results. Native bridge token capture, acoustic-model compatibility, real audio, and Android performance are separate verification owned by the model and engine workstreams.
