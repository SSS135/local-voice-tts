# LocalVoice architecture and backend contract

LocalVoice is a separate Android system TTS engine (`org.localvoice.tts`). A client uses Android `TextToSpeech`, selects an advertised voice and receives mono PCM through the normal framework service. It does not depend on VN Reader being installed. VN Reader source was consulted read-only for the Edge protocol; the reused code and its notices are included in this GPL application.

## Responsibilities

| Component | Owns |
| --- | --- |
| `Catalog` | Loads and strictly validates `app/src/main/resources/org/localvoice/tts/models.json` (https-only URLs, 64-hex SHA-256, positive sizes, known backend IDs; fails fast at startup): stable model/voice IDs, language and network capabilities, backend ID, adapter configuration, pinned download revision, file sizes/SHA-256 and license metadata. |
| `MainActivity` | User selection, installation progress, explicit online consent, preview and links to Android TTS settings. |
| `ModelStore` (facade) / `ModelInstaller` / `ModelDownloader` / `ModelFiles` | `ModelStore` owns the single storage worker, jobs, progress and installed snapshot; `ModelInstaller` stages, verifies and atomically publishes; `ModelDownloader` is the only HTTPS client. Private model storage, verified staging/activation, download cancellation and retry, installed state, preferences and online opt-in. They do not create inference sessions. |
| `LocalVoiceService` | Android language/voice discovery, request validation, `SpeechPlan` segmenting/word timing/silence shaping, a look-ahead render worker, float-to-PCM16 conversion, `rangeStart` word markers, callback start/audio/terminal handling, request cancellation. It selects adapters from catalog metadata; it contains no Kokoro/Supertonic model-ID branch. |
| `CheckVoiceDataActivity` | Legacy local-resource-data result, inspected on a worker so a cold main-thread installed snapshot cannot produce a false missing-data result. |

Model installation state is independent of loaded model state. Discovering voices must not load a model or make a network request. Offline synthesis opens only verified installed files. Download/update work and preferences stay outside the service adapter contract.

Modern `getVoices()` discovery includes enabled Edge metadata and marks those voices network-required; `isLanguageAvailable()` counts an online voice only when it is the selected voice (SEC-004), otherwise an online-only language reports `LANG_MISSING_DATA`. `ACTION_CHECK_TTS_DATA` reports installed local resources plus the selected online voice's locale (metadata only), using ISO-3 language/country entries; Android Settings enables Play and the rate/pitch sliders only when its default locale is listed. With zero local models and no selected online voice it returns `CHECK_VOICE_DATA_FAIL`. `ACTION_GET_SAMPLE_TEXT` accepts ISO 639-1 (Settings) and ISO-3 codes and returns `LANG_NOT_SUPPORTED` for languages without a bundled sample, so Settings uses its own localized string. Locale requests (`setLanguage`, client default locale, `getDefaultVoiceNameFor`) resolve to the manager-selected voice whenever its language matches; region only ranks the remaining voices, and `isLanguageAvailable` reports installed local coverage plus the selected online voice's language, i.e. exactly the languages a locale-only request can speak. `getDefaultVoiceNameFor` returns a stable per-language alias (`default:en`, `VoiceResolver`) that resolves to the current selection at synthesis time: `setLanguage` stores that name in the client and browsers call it only when the page language changes, so a concrete id would pin the voice selected at bind time. `getVoices()` lists these aliases (required by `setLanguage`), per-model quality/latency from the catalog, and uninstalled downloadable local voices with `KEY_FEATURE_NOT_INSTALLED` (never valid for `setVoice`). Explicit voice names resolve exactly; a retired id (catalog voice `aliases`, e.g. `pocket-en-alba:alba`) maps to its successor, the saved selection is migrated the same way, and an unknown or uninstalled name falls back to an installed local voice of the request language (never an online voice) instead of `ERROR_NOT_INSTALLED_YET`. Metadata callbacks must stay cheap: Chromium-based browsers call `isLanguageAvailable` for ~900 locales on every engine bind, so binder-thread `ModelStore.isInstalled` serves the cached install snapshot (async refresh) and synthesis re-verifies files. The post-suite worker fix passed a cold public intent with English US/UK and Russian available and no missing installed language.

Downloads run in the application process. Keep the app in the foreground until installation completes; this release does not promise unattended/background download completion. If Android kills the process, the user retries explicitly. Completed verified staging files are reused on retry, while a partial file restarts from its beginning. `StorageSelfTest` (run by `gradlew test`) exercises the disk installation rules.

Main-thread installed-state polling uses worker-owned snapshots and does no model-file I/O; until a model's first snapshot exists the UI shows `Checking…`, never "Not downloaded". The first refresh is queued ahead of orphan cleanup, and every snapshot write (`ModelStore.recordInstalled`, from any thread) that changes a value notifies listeners. Generic per-file cache records require revision/hash/size plus device/inode/mtime/ctime identity; API-26, coarse, fresh or future identities conservatively rehash. Weak records never become trusted merely by aging. This generic cache policy is distinct from the following download-job proof.

The 1.1.1 downloader writes with exclusive creation/no-follow, forces and closes the sole writer, then performs one stored-byte SHA. Eligible large fresh files retain at most 16 read descriptors with FD/path identity. On supported Android versions a separate job-local proof can use app-owned, single-link, reversible0400 permissions set through the descriptor before SHA; final FD/path identity and mode must still match. Small, unsupported, reused and imported files receive ordinary final verification. Coarse timestamps alone never authorize cache trust. Root or hostile same-UID code that chmods, writes and restores mode within one coarse tick is outside the exclusive private-WORK namespace boundary; this is not fs-verity or cryptographic immutability.

Only a successfully atomically created, no-follow-checked staging leaf skips the initial reuse scan. Old empty/partial/corrupted/salvaged stages still scan and hash reusable files. Download-only path plans are lexical; strict original-root→leaf no-follow checks remain at actual write/hash/final boundaries, including after HTTP waits. Generic path resolution and imports retain their existing checks. Every file passes a final barrier and held descriptors close before receipt and atomic activation. Blocking receipt/cleanup I/O occurs outside the brief cancel/atomic-rename monitor; accepted cancellation cannot publish Ready, while a completed atomic commit cannot later become Cancelled.

Whole-job **Downloading and checking** covers connection, transfer and per-file checking with one cumulative byte total. Ordinary updates obey200 ms cadence; SHA does not add downloaded bytes. Initial and final/terminal phases remain immediate. Conditional UI setters preserve changed progress, retry, availability and metadata while leaving unchanged card text alone. See [VERIFICATION-PROFILE.md](history/VERIFICATION-PROFILE.md) for measured scope, exact counters and limits; process-wide counters may include background snapshot work.

Explicit repair can reuse an invalid installed directory when no staging directory already exists. The worker removes the old receipt, discards its verification-cache records and atomically moves that directory into unadvertised staging. Every staged file is verified against the pinned size/hash; only damaged or missing files are transferred. An existing staging directory is preserved, and a valid installed package returns without moving or downloading. Cancellation after salvage keeps the stage available for explicit retry while the model remains unavailable. Repair still uses the final all-file barrier and atomic publication; the old receipt or weak cache never authorizes reuse by itself.

## Adapter API

`SpeechBackend` is a synchronous Java interface:

```java
void load(File directory, Map<String, String> config) throws Exception;
int sampleRate();
void synthesize(String text, String languageTag, int speakerId, float speed,
                Cancellation cancellation, PcmSink sink) throws Exception;
void cancel(); // concurrent, best effort; never frees inference resources
void close();
```

Adapters can also implement optional `setHost(SpeechBackend.Host)`. The service factory supplies that host before load; it exposes network availability, a cancelable connectivity/backoff wait and phase/attempt status reporting. Local adapters can retain the default no-op implementation. This keeps Android connectivity/UI code outside the reusable retry/PCM helpers and avoids a service branch for a particular model.

`PcmSink.write(float[])` returns whether output should continue. Each array contains mono float samples at `sampleRate()`. Adapters should supply finite samples in the normal -1..1 range; the Android boundary clips to PCM16. `sampleRate()` is valid after successful `load`. PCM callbacks occur on the synthesis caller thread and end before `synthesize` returns. Adapters must not retain the sink for asynchronous writes. The sink consumes an array before returning; an adapter can then reuse its storage.

The coordinator calls `Ready.onReady(sampleRate)` before inference so Android output is initialized before the first PCM block. Initialization, local synthesis and fatal online failures propagate to the service, which reports a synthesis/network error for a live request. Recoverable Edge transport/validation failures stay inside its retry loop without completing the Android request. A failed load is closed immediately and is never cached as a successfully loaded adapter. A later request can retry. `close` must be idempotent and release all native sessions, sockets and temporary decoder resources owned by the adapter.

`SerializedBackend` caches the model ID, backend kind, directory and a copied configuration map. A change in any of them releases the previous adapter before loading its replacement. In particular, two Edge voices share one model ID but use different `voice` configuration: changing Aria to Guy must reload that configuration. A stable identical configuration reuses the existing session. Language, speaker and speed passed to `synthesize` remain request parameters.

## Segments, word timing and gaps

Clients such as Edge Read Aloud and Chromium send one paragraph piece per `speak(QUEUE_FLUSH)` and the next only after `onDone`, so the audible gap between pieces is next-request first-audio latency plus edge silence. Edge highlighting and its resume/tap-word offset come only from `onRangeStart`; Chromium does not forward `onRangeStart` to Web Speech `boundary` events.

- `SpeechPlan.Planner` cuts the original text at sentence ends, one segment at a time; the first segment is ≤60 characters (clause cut, no remainder under 24 characters), later ones pack whole sentences and grow 1.5× up to 140 (`segmentLimit`). `chunking=backend` adapters get whole sentences only; `chunking=stream` (Edge) gets whole paragraphs up to `segmentLimit`, packed from the first segment.
- A single render worker (`LocalVoice-synth`) renders segments ahead of playback, bounded to 4 s of unplayed audio. Android blocks `audioAvailable()` beyond 500 ms queued, so rendering on the callback thread underran at every chunk boundary.
- Render budget: each later segment is also capped (`SpeechPlan.budgetLimit`, floor 40 characters) to what the model renders, at its learned ms per character, within 80% of the audio still queued ahead. Models rendering slower than real time (Kokoro on a loaded Pixel 7 Pro, render/audio 1.2-1.6) keep the growth limit: they stall at any size. Without it a short first sentence followed by a long one stalled playback mid-paragraph (Supertonic 0.3-1.2 s, Pixel 7 Pro).
- Each segment's PCM is shaped: utterance lead ≤20 ms, tail ≤100 ms; between segments the trailing silence is set to the boundary's pause (sentence 300, paragraph 450, clause 150, word 40 ms), divided by the speech rate. Pocket emitted about 230 ms of leading silence per chunk. Streamed segments hold silence after the latest sound back and shape it the same way at the segment end; silence inside the segment stays.
- Before writing a segment, the service calls `SynthesisCallback.rangeStart` once per word (letters/digits runs, original-text UTF-16 offsets). Edge uses Microsoft `WordBoundary` metadata (`PcmSink.word`); local models expose no word timing in sherpa-onnx 1.13.8, so words are spread over the segment's voiced span by a letter/digit/punctuation weight.
- Adapters whose `streams()` is true (Pocket, NeuTTS, Edge) play their first segment block by block; markers come from the adapter when `timesWords()` (Edge), else from a per-model speaking rate learned from earlier segments.
- Paragraph handoff (`TailHandoff`, setting "Short pauses between paragraphs", default on; request param `paragraph_handoff=false` disables it): Chromium/Edge send the next paragraph only after `onDone`, which fires once handed audio has played, so the next request's first-audio latency was an audible gap. The service holds back the request's last `holdMs` (learned first-audio latency + 300 ms, 0.4-2 s, plus up to 1 s to cut at a pause), calls `done()`, and stays current ("linger") until `onStop`. A request arriving within 250 ms of that stop, not before the handed audio ended (−300 ms), from the same caller and not a suffix of the previous text, plays the tail first (followed by a paragraph pause: 450 ms, model config `paragraphPauseMs`; Edge 600 ms, Microsoft Ava's own trailing plus leading silence per paragraph) while its own first segment renders; its markers sit after the tail. A request queued behind the previous one (no stop at all, QUEUE_ADD) also continues it, and that caller holds nothing back afterwards. Otherwise the tail is dropped: tap-to-seek arrives while audio still plays, re-speaking part of the same paragraph is a seek. A stop while the handed audio still played is a user stop; a stop after it ended with no request within 250 ms (Edge stops right after the last paragraph's `onDone`), or no stop or request within 700 ms of its end, means reading ended: the tail plays on the service's own `AudioTrack` (off the synthesis thread; a new request first stops it and can claim the rest) with the request's audio attributes, without taking audio focus. Stopped while a claimed tail plays and before any own word (Edge pause): only a resume of that text replays it. `synthesizeToFile` never holds back. A live segment is held only when the model renders at <0.5× real time (Edge), since holding delays its own first audio. The tail's words get no `rangeStart`. A next request with another voice still plays the tail first (resampled when its rate differs, once that rate is known); a changed speech rate does not re-render it.
- A segment the loaded local model rejects is skipped as a pause; a request that yields no audio completes silently. Load and online failures remain errors: Edge Read Aloud skips the rest of a paragraph on any error. An online fragment Microsoft declines (see Edge retry) is silent, not an error.
- `onLoadLanguage`/`onLoadVoice` preload the resolved local model on the render worker; they never go online or cancel a request. Only the latest preload runs, 1 s after it was asked for, and a request supersedes pending ones: clients call `onLoadLanguage` at bind and `setVoice` up to ~0.6 s later (probe), and a different model in between cost a whole extra load (Kokoro 2.4-3 s) before the voice's own. A loaded model stays loaded until another model is needed or the service is destroyed. Pixel 7 Pro (hot, throttled), 46-character sentence: load Supertonic 1.15 s, Kokoro 2.2-3.0 s, Pocket 1.0 s; first inference after load is not measurably slower than warm (Supertonic 1329 vs 1346 ms, Kokoro 3853 vs 3685-3734 ms, Pocket first PCM 826 vs 784-815 ms), so no warm-up synthesis runs.

## Cancellation and lifetime

`begin()` creates a generation token. A later `begin()` or `cancel()` invalidates earlier tokens. `execute()` checks that token before load, after load and at PCM delivery. Once a sink returns false, the coordinator keeps that sink closed for the remainder of that inference even if the backend keeps calling it. A new generation is independent of an earlier stop.

`cancel()` does not acquire the inference or output sink lock. It invalidates the generation immediately and invokes the adapter's concurrent best-effort `cancel()`. An output callback already in flight may finish; the service checks cancellation while converting/buffering PCM, and the Android framework rejects stopped output. The coordinator does not hold a cancellation lock while calling a possibly blocked Android sink.

Load, synthesis, model switching and close share one inference monitor. Replacement and destruction wait until active native inference has returned; they never free a native model in use. An adapter's concurrent `cancel()` may interrupt network I/O, but must not unload model/decoder resources concurrently with synthesis.

Service destruction invalidates the active generation immediately and schedules serialized adapter cleanup off the main thread. Each client owns its playback/queue and must use its own Stop/queue-flush control; the manager stops only its own preview client. Voice validation/preloading through `onLoadVoice` does not cancel an already valid queued request.

**Supertonic limitation:** sherpa-onnx 1.13.8 can ignore the native callback's stop return value. Stopping audio therefore does not guarantee immediate termination of native computation. Obsolete PCM is discarded, and the service limits each request segment to at most 140 characters (`SpeechPlan.LIMIT`). This bounds the pending text segment, not a guaranteed stop duration. Model switch/unload waits for that inference to finish. The contract test deliberately uses a stubborn fake that continues callbacks after stop to verify this behavior.

## Online boundary and privacy

Edge is disabled initially. The user explicitly enables its online capability and chooses an online voice. Android voice metadata marks it as requiring a network connection. A failed local voice never silently falls back to Edge. Recoverable Edge failures wait/retry the same pending text; fatal configuration/authorization failures report an error.

The repository initializes bundled/private cached Edge metadata asynchronously without HTTP, including headless service startup. Its bundled snapshot has 322 voices and 142 locales. Explicit refresh is bounded to 20 seconds and 1 MiB, validates the entire snapshot, and atomically replaces the private cache/catalog. Voice IDs remain `edge:ShortName`; the original four IDs stay valid. Disabling online capability revokes its preference and discovery immediately, outside the storage work queue; the service rechecks consent and cancels an active matching online request, leaving local synthesis unaffected.

Actual cold headless discovery exposed 322 network voices among 372 total with all local models installed. An offline request stayed pending until explicit UI Disable, then surfaced an error without PCM/successful done. Restoring Wi-Fi did not revive the revoked request; subsequent discovery exposed 50 local/zero network voices. Production French `fr-FR-DeniseNeural` also generated PCM. The 236,398 ms error timestamp in the callback log includes Android freezing the caller and is not a cancellation-latency measurement; the live pending interval before revocation was about 160 seconds.

Online selection rule (SEC-004, `LocalVoiceService.chooseForSynthesis` / `onGetDefaultVoiceNameFor`): an online voice is used only when the client names it or it is the voice selected in Local Voice. A language-only request never falls back to an unselected online voice, and a request with `KEY_FEATURE_EMBEDDED_SYNTHESIS=true` never uses an online voice (an installed local voice for the language is used instead, else the request fails). `getVoices()` reports `KEY_FEATURE_NETWORK_SYNTHESIS` for online voices and `KEY_FEATURE_EMBEDDED_SYNTHESIS` for local ones.

Only a synthesis request for a selected online voice sends its text to Microsoft's service. Catalog display, local voice discovery and selecting a local voice do not contact Microsoft. The UI discloses the recipient, network requirement and unofficial endpoint. Microsoft's consumer service availability and terms apply independently of the application license.

Each paragraph (`chunking=stream`, ≤1000 characters, `EdgeBackend` further splits at 3000 escaped bytes) is one server turn, streamed: the listener splits the MP3 payload into whole MPEG frames (`EdgeAudio.frameLength`), `MediaCodec` decodes them as they arrive, and each decoded buffer goes to the sink at once, preceded by the `WordBoundary` markers it covers. A turn is bounded to 2 MiB of MP3 and 4,320,000 finite float samples (180 s at 24 kHz); an incomplete final frame is dropped. One request per paragraph keeps Microsoft's own sentence pauses and pays one connection; per-sentence turns (≤140 characters, whole-turn download and decode) cost 1.8-3 s first audio per paragraph and multi-second stalls between turns on the Pixel 7 Pro. Once a turn's first audio arrives the adapter opens one spare connection for the next turn (no text is sent on it until then; discarded after 30 s or when the server closes it), saving the 0.75-0.9 s TLS/WebSocket handshake. First-audio latency must be measured at first PCM delivery, not at WebSocket connection or output `start`.

### Edge retry and chunk commit

`EdgeProtocol.classify` sorts each failed server turn (sources in its comment: edge-tts 7.3.1, RFC 6455, Azure 1007 reports):

| Signal | Class | Behaviour |
|---|---|---|
| `turn.end` with no audio; close 1007/1008 | declined | no retry; fragment is silent, reading continues; logs voice/phase/code, never text; after 3 in a row for a voice: transient (outage guard below) |
| device offline | transient | waits without limit, outside the time budget, unless the client set either network key |
| connect/DNS/handshake/socket failure, attempt timeout, HTTP 408/409/425/429/5xx, other closes (1000/1001/1006/1011…), malformed/truncated/decode-failed audio | transient | retry with backoff within the budget |
| HTTP 401/403 | auth | resync `Sec-MS-GEC` clock from the `Date` header, retry once immediately, then fatal |
| other HTTP 3xx/4xx (SSML is sent only after the upgrade, so never content), close 1002, unsupported codec/format, invalid voice metadata | fatal | no retry, `ERROR_SERVICE` |

Transient failures keep the same uncommitted text chunk pending. An attempt times out after 45 s (or the client's network timeout, if shorter) without a new MP3 frame or decoded block, not after a fixed turn length: a paragraph turn streams as long as its audio keeps coming. Expiration triggers a new attempt rather than abandoning the chunk. While the device reports a network, each server turn's retry loop is bounded by the client's `KEY_FEATURE_NETWORK_TIMEOUT_MS` (default 120 s, `RequestPolicy`) and `KEY_FEATURE_NETWORK_RETRIES_COUNT` (default unbounded); exhausting the time budget reports `ERROR_NETWORK_TIMEOUT`, the retry count `ERROR_NETWORK`. Outage guard (`EdgeRetry.DeclineGuard`, static per voice across requests): empty turns also come from voice-wide outages/throttling (edge-tts issues 473, 481), so after 3 consecutive declined fragments further declines for that voice retry as transient until a fragment returns audio (which resets the streak); exhausting the budget then reports `ERROR_NETWORK`. Up to 3 fragments of an outage are still skipped silently. Exponential backoff starts at 250 ms, uses jitter and caps normal waits at 15 seconds; offline connectivity waits avoid issuing requests without an available network and can wake when connectivity changes. A server `Retry-After` delay can span multiple bounded waits. Stop is checked during waits and before/after an attempt.

A turn that fails before any PCM left retries the same text. A turn that fails after PCM left retries from the start of the word then being spoken (the latest placed `WordBoundary`; the turn start when none was placed), so recovery may repeat at most that word and never replays the whole turn. A rejected/stopped sink ends the turn and is never treated as a transport failure to replay. A fatal invalid voice/configuration, authorization rejection or incompatible protocol response exits with an error, without skip, success or fallback.

Framework Stop/queue replacement and revoking online capability invalidate the active request generation (a changed saved voice applies from the next request and never cancels a client's active one) and cancel in-flight I/O/backoff. A late successful result is checked against cancellation before commit, and staged PCM checks it between blocks. Later `QUEUE_ADD` requests stay behind the live pending head request, preserving order until recovery or cancellation. The retry helpers do not own a second persistent queue; cancelling its head request does not clear another client's full framework queue. Disabling online voices removes them from discovery and queued requests that still name those disabled voices fail as unavailable instead of resuming network speech. Changing a saved default does not rewrite another client's explicitly selected queued voices.

This guarantee applies only while the same live client request remains pending. Android process death, OEM process management, client shutdown and explicit/automatic client Stop end that request; the engine cannot override them or reconstruct a lost client queue. Source review found no wall-clock idle timeout in the AOSP synchronous synthesis/playback/file callback path used here. Unchanged VN Reader automatic narration has its own **600,000 ms (ten-minute) timeout per prepared text chunk**; it stops/reports a problem after that limit. VN Reader's normal TTS completion/settings preview has no corresponding outer narration timeout, while its 15-second engine initialization timeout concerns startup. LocalVoice does not change any VN Reader file or promise automatic narration recovery beyond that caller's limit.

## Adding an engine

1. Implement `SpeechBackend` in the backend package. Keep model-specific APIs, tokenization and decoder/network code inside the adapter. Validate required configuration at load. Load no model from a voice-discovery/UI callback. Respect synchronous PCM, best-effort cancellation and idempotent cleanup.
2. Add one factory to `BackendRegistry` under a stable backend ID. No service model-ID condition is needed. The factory constructor should be cheap; allocate inference resources in `load`.
3. Add catalog model/voice metadata with that backend ID, supported language tags and actual speaker IDs. Pin each downloaded artifact to an immutable revision, HTTPS URL, exact size and SHA-256. ## Performance baseline

The intended minimum device targets are Pixel 7 Pro and Huawei Pura 70. The portable implementation uses ARM64 CPU inference and quantized local models; it requires no Google Play Services, NNAPI, GPU/NPU provider or Google-specific accelerator. The sherpa runtime also contains an x86_64 emulator ABI for integration verification.

Current defaults are two CPU inference threads, one native sentence per generation call, eight Supertonic generation steps and `SpeechPlan` segments (first ≤60 characters, then growing to ≤140). Backend load configuration accepts `numThreads` clamped to 1..4 and Supertonic `numSteps` clamped to 2..16; no tuning UI is exposed. For on-device A/B, the request param `numThreads` (1-4, local models only) overrides the catalog value for that request; a changed value reloads the model. Two threads is a conservative CPU baseline that avoids consuming every core; eight steps preserves the runtime's intended quality baseline. Chunking trades some prosody and throughput for bounded pending work and earlier opportunity to honor stop. Thread/step alternatives must be measured with identical text, model revision, speaker and audio duration before changing these defaults. The adapter supplies the actual sample rate: the tested Supertonic runtime reports 44.1 kHz, while Kokoro uses 24 kHz.

Record cold model load, warm first-PCM latency, synthesis wall time, generated audio duration/real-time factor and process memory separately. Compare threads/steps with repeated warm requests, and separately verify stop/switch latency. Emulator numbers measure that emulator/host setup only. They are not Pixel/Huawei speed, thermal, battery or sustained performance measurements. Physical-device and extended thermal checks remain required before claiming the minimum devices meet a numerical performance target.
