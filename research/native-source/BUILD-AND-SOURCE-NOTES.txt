Build path on Linux/macOS with Android SDK/NDK and CMake installed:
1.Extract sherpa source ZIP.
2.Set ANDROID_NDK to the chosen Android NDK root. Upstream GitHub workflow uses its runner's ANDROID_NDK_LATEST_HOME, so the exact NDK version of the published AAR is not pinned in source. This prevents a claim of byte-for-byte reproducibility from source evidence alone.
3.Set SHERPA_ONNX_ENABLE_C_API=ON; SHERPA_ONNX_ENABLE_JNI=ON; SHERPA_ONNX_ENABLE_TTS=ON; SHERPA_ONNX_ANDROID_PLATFORM=android-21.
4.Run ./build-android-arm64-v8a.sh and ./build-android-x86-64.sh. Scripts call CMake with the NDK toolchain, Release mode and JNI/TTS enabled. Install outputs appear in each build directory's install/lib.
5.The upstream workflow assembles all four ABI native directories plus Kotlin API into the Android AAR using its documented Gradle project. Use source .github/workflows/android.yaml for exact copying/Gradle steps rather than guessing packaging.

Dependency source pins are explicit in sherpa cmake/piper-phonemize.cmake and piper CMakeLists.txt. Build may also fetch pinned permissively licensed support dependencies and ONNXRuntime prebuilt native libs; these are described by the full CMake source tree. ONNXRuntime MIT license cached research/ONNXRUNTIME-LICENSE. A fully offline native rebuild may require caching those additional downloads; this worker has not attempted it. The exact compiler/runner environment and binary bit-reproduction are unverified. This source package is evidence/source preservation, not a claim of legal certification or completed independent native rebuild.
